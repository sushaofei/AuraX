# 对话执行轨迹产品方案

跟踪 Issue：[AuraX #2](https://github.com/sushaofei/AuraX/issues/2)。

## 产品目标

在对话正文右侧提供可展开或收回的执行轨迹，让用户在不离开当前 Session 的情况下理解模型、
MCP/Capability、Tool、Skill、Resource、审批与 Run 状态之间的时间关系。轨迹用于解释与诊断，
不替代 transcript 或最终结果。

## 信息架构

- 主对话继续占据页面主要宽度，负责用户/助手消息、结果与审批操作。
- 执行轨迹在宽桌面下是约 380px 右栏；收回后保留带节点计数的打开按钮。
- 可用宽度不足时轨迹作为覆盖式右抽屉，带遮罩和 Escape 关闭，不压缩对话内容。
- 节点按 Run 分组；“会话”组展示不属于某个 Run 的生命周期事件。
- 每个节点默认展示图标、标题、状态、时间和摘要，详情通过原生 button/region 展开。

## 节点体验

节点类型包括用户输入、模型输入、模型输出、Tool/MCP、Skill、Resource、审批、Run 和 Session。
requested/completed 不是两个视觉节点，而是同一节点从 running 变为 completed/failed/waiting。

面板提供“全部 / 模型 / 能力 / 状态”筛选。筛选只改变展示，不改变缓存或服务端读取。
running、waiting、completed、failed、cancelled 使用颜色与文本双重编码，不能只靠颜色表达状态。

详情字段使用描述列表；JSON 参数/结果使用可换行的等宽预览。服务端已经脱敏和限长，前端仍不把
详情写入 localStorage、日志或错误遥测。

## 数据与恢复

AuraX 只通过 `@aurax/claw-sdk` 调用 `/v1/tasks/{session_id}/activity`。首次读取完整页，后续按
`after_version` 读取增量；同 ID 节点仅接受更大的 `updated_version`。SSE 只触发 query
invalidation。刷新、重连、应用重启与 SSE cursor reset 都从 Activity Query 恢复。

localStorage 只记录 `executionTraceOpen` 和筛选偏好。切换 Session 时保留面板偏好，但节点由新的
query key 隔离。

## 可访问性与异常

- 面板开关暴露 `aria-expanded`/`aria-controls`；抽屉保留明确 label、关闭按钮和 Escape 行为。
- 节点详情按钮可键盘操作，状态文本可由屏幕阅读器读取。
- loading 使用文本/骨架，empty 解释尚无活动，error 提供显式重试。
- 后端旧版本返回 404 时，对话保持可用并显示“当前 AuraClaw 不支持执行轨迹”。
- 长标题、长 Tool 名、长 JSON、缺失时间与未知节点类型均不得破坏布局。

## 验收

- 多 Run 节点分组稳定，生命周期不重复，当前状态能随 Query 刷新更新。
- 展开/收回、筛选与节点详情在刷新后符合持久化规则。
- 960px 与 1440px 视口均可操作，Escape 能关闭窄屏抽屉。
- SDK 单测、TypeScript strict、lint 与 Playwright 覆盖关键路径。
